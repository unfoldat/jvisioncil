# 콘텐츠 구조 → 접근성 마크업 원칙

`content-structure-a11y` 스킬(claude.ai 쪽에만 있어 이 저장소 밖)의
핵심 내용 요약. 콘텐츠를 마크업할 때 "시각적으로 어떻게 보이는가"가
아니라 "사용자가 실제로 그 데이터를 어떻게 소비하는가"를 기준으로
HTML 요소를 고른다.

## 자료구조 ↔ 마크업 대응표

| 자료구조 | HTML | 판별 질문 |
|---|---|---|
| 스칼라(단일 값) | `<p>` | 나눌 하위 구조가 없는가? |
| 배열(독립 항목들) | `<ul><li>` | 각 항목이 그 자체로 완결된 정보 단위인가? |
| 순서 배열 | `<ol><li>` | 순서를 바꾸면 의미가 깨지는가? |
| 딕셔너리(1세트) | `<dl><dt><dd>` | 행이 여러 개 반복되지 않는가? |
| 레코드 배열(동일 스키마) | `<table>` | 속성 하나를 세로로 비교하며 훑는가? |
| 트리(부모-자식) | 중첩 heading + list/table | 부모 값을 지우면 자식이 의미를 잃는가? |

## 표 vs 목록 판별 기준

표 자격의 두 조건(둘 다 필요): ① 각 행이 완결된 레코드 ② 모든 레코드가
동일한 속성 집합을 공유. 이 둘을 만족해도 결정적인 세 번째 조건은
**"사용자가 속성 하나를 여러 레코드에 걸쳐 세로로 비교하는가"** —
Yes면 표, No(레코드를 하나씩 완결 소비)면 목록. 스키마가 같아도
소비 패턴이 행 단위면 목록이다(예: 강의 종류 카드).

## 병합 셀 원칙

병합 셀(colspan/rowspan)을 만나면 구조가 잘못 우겨넣어졌다는 신호 —
두 원인을 구분한다.
- **"이하동일" 압축**: 데이터는 flat인데 시각적으로만 반복 생략. →
  셀을 지우지 말고 모든 행에 값을 다 채운다(스크린리더는 "이하동일"을
  유추 못함). 반복이 거슬리면 CSS로만 흐리게.
- **진짜 부모-자식 계층**: 상위 값이 없으면 하위가 의미를 잃는 관계.
  → 표 하나에 우겨넣지 말고 카테고리마다 `<h4>` + 그 아래 목록/표로
  쪼갠다.

## 오늘(2026-08-26) 실제 적용 사례

- **강사 프로필 학력 표**: 동일 스키마(학위-학교) 레코드가 반복되고
  세로 비교가 자연스러워 `<table>` 유지. 반면 `bio`(약력 리스트)는
  레코드를 하나씩 완결 소비하므로 `<ul>`.
- **소식 카드**: 제목/날짜/요약이 한 카드 안에서 완결 소비되는
  레코드 — 목록(`<li>`)이며, 카드 간 속성 비교는 일어나지 않음.
- **강의 카드**: 대상/배지/설명/시간이 스키마는 같지만 사용자는
  카드 하나씩(자신에게 맞는 강의)을 완결 소비 — `<ul><li>` 유지,
  표로 바꾸지 않음.
